# Design Audit Reading Site

Use this skill when reviewing Proustian visual design for Quartz or the future web app.

## Purpose

Audit whether the surface supports sustained reading. This skill judges fit and risk; it does not redesign or patch unless the user explicitly asks for implementation.

## Design Direction

Preferred mood:

- dark archive
- observatory
- reading chamber
- manuscript texture
- memory palace
- textual apparatus

Avoid:

- SaaS style
- generic card grid
- bright cheap yellow
- marketing CTA
- LMS aesthetics
- crowded dashboards
- admin dashboards
- generic AI cards
- navigation pressure that overwhelms reading

## Workflow

1. Identify the surface: Quartz page, app shell, text chamber, or plate map.
2. Check whether Proust remains visually and conceptually central.
3. Check hierarchy, spacing, typography, contrast, and reading width.
4. Check whether navigation helps the reader without becoming the main event.
5. Check whether Language Training, System, and Daily remain service layers, not the center.
6. Check whether components serve close reading rather than product marketing.
7. Flag blog, LMS, SaaS, admin dashboard, or generic AI drift.

## Output Shape

- Surface audited
- What supports reading
- Risks
- Required changes
- What not to change

## Rules

- Do not redesign Quartz unless asked.
- Do not implement a web app unless approved.
- Do not add decorative complexity that weakens reading.
- Do not use marketing language for reader-facing tools.
- Do not make secondary systems more visually central than Proust.
- Do not turn an audit into a full rewrite plan unless requested.
